## 改动一：#7b 修复 admin.service.ts 三处 N+1 查询

### 核实结论
- `getTeamMemberSummaries`（L200-218）：每个 teamMember 单独 `findUnique user`。
- `getReviewQueue`（L246-279）：`version.findMany` 仅按 status 过滤（**跨租户全表扫描**），再 JS `projectIds.includes` 过滤；每个 version 两次 `findUnique`（document + project）= 双重 N+1。**有数据隔离隐患**（其他租户的 version 行先进内存再 JS 过滤）。
- `getTeamOverview`（L93-100）：每个 project 单独 `count projectMember`。

### 方案（返回类型零变化，前端无感知）
1. **`getTeamMemberSummaries`**：改 `findMany({ where:{teamId}, include:{ user:{ select:{displayName,email} } } })`，单次 JOIN。
2. **`getReviewQueue`**：
   ```ts
   this.prisma.version.findMany({
     where: {
       status: { in: ["pending_review", "submitted"] },
       document: { projectId: { in: projectIds } },  // 源头收窄，消除跨租户全表
     },
     include: { document: { select: { id, title, project: { select: { id, name } } } } },
     orderBy: { createdAt: "desc" },
   })
   ```
   消除双重 N+1 + JS 过滤 + JS sort。
3. **`getTeamOverview` memberCount**：改 `groupBy({ by:["projectId"], where:{ projectId:{ in } }, _count:{_all:true} })`，建 Map 合并。

### 涉及文件
- `apps/api/src/admin/admin.service.ts`（3 处方法改写）

### 验证
- `npm --workspace @dramaflow/api test`：现有 "team admin permissions" 测试（L1850-2073）只断言权限字段，无字段级断言，不受影响。

## 改动二：#19/#20/#26 契约收敛（3 子项）

### 核实结论
- **#19**：schema.prisma L30-39 的 `enum ProjectPermission`（下划线风格）**全 schema 无任何 model 字段引用**，是幽灵 enum。运行时用 shared 的点号风格。src 代码无 `Prisma.ProjectPermission` 引用。
- **#20**：`video-providers/types.ts:11` 的 `NormalizedVideoProviderStatus` 与 shared `JobStatus`（domain.ts:104）字面量完全相同。
- **#26**：worker `index.ts` 零 import shared，L84 内联 `as { id?: string... }`。worker 的 `package.json` 已声明 `@dramaflow/shared:*` 依赖但没用。

### 方案
1. **#19 删幽灵 enum**：
   - schema.prisma 删除 L30-39 的 `enum ProjectPermission { ... }`。
   - 新迁移 `000003_drop_project_permission_enum/migration.sql`：`DROP TYPE "ProjectPermission";`（安全，无列依赖）。

2. **#20 NormalizedVideoProviderStatus 改别名**：
   - `video-providers/types.ts`：加 `import type { JobStatus } from "@dramaflow/shared"`，L11 改为 `export type NormalizedVideoProviderStatus = JobStatus;`（保留语义名称，消除字面量重复，零破坏）。

3. **#26 worker 接入 shared**：
   - `worker/src/index.ts`：加 `import type { JobRecord } from "@dramaflow/shared"`，L84 改为 `as Pick<JobRecord, "id"|"type"|"retryCount"|"maxRetries"> | null`（窄类型，比内联更准确——`id` 在 JobRecord 是必填）。

### 涉及文件
- `apps/api/prisma/schema.prisma`（删 enum）
- `apps/api/prisma/migrations/000003_drop_project_permission_enum/migration.sql`（新建）
- `apps/api/src/jobs/video-providers/types.ts`（L8/L11）
- `apps/worker/src/index.ts`（import + L84）

### 验证

- `npm --workspace @dramaflow/api test` + `npm --workspace @dramaflow/worker test`

## 改动三：#22/#23 收敛散落定义

### 核实结论
- **#22 默认 model**：web `image-config.ts:54-65` 的 `getDefaultVideoProviderModel` 与 5 个 API adapter 的默认 model **完全一致**（gen3a_turbo/video-01 等）。图片侧有语义不一致：API 用 `gpt-image-1` 作 openai-compatible 默认（`media-generation.provider.ts:50`、`jobs.service.ts:1187`），web 没写。shared 零收敛。
- **#23 ProjectInviteRecord**：legacy 和 workspace.service 各一份，字段实际等价（`ProjectMemberRecord["role"]` ≡ `ProjectRole`）。shared 缺失。

### 方案
1. **#22 在 shared 新增常量映射**（`packages/shared/src/providers.ts`）：
   ```ts
   export const DEFAULT_VIDEO_PROVIDER_MODELS: Record<VideoGenerationProvider, string> = {
     "grok": "grok-imagine-1.0-video", "minimax": "video-01",
     "volcengine": "doubao-seedance-1-5-pro-251215", "vidu": "viduq3-turbo",
     "ali": "wan2.6-i2v-flash", "runway": "gen3a_turbo", "openai-compatible": "",
   };
   export const DEFAULT_IMAGE_PROVIDER_MODELS: Record<ImageGenerationProvider, string> = {
     "google-gemini": "gemini-3.1-flash-image-preview", "grok": "grok-imagine-1.0",
     "openai-compatible": "gpt-image-1", "stable-diffusion": "", "comfyui": "",
   };
   ```
   - web `image-config.ts`：`getDefaultVideoProviderModel`/`getDefaultImageProviderModel`/`toImageGenerationConfigDraft` 改用常量。
   - 5 个 API video adapter：`input.config.model || "xxx"` 改为 `|| DEFAULT_VIDEO_PROVIDER_MODELS[<provider>]`。
   - 图片侧 `media-generation.provider.ts:50` + `jobs.service.ts:1187`：`gpt-image-1` 改用 `DEFAULT_IMAGE_PROVIDER_MODELS["openai-compatible"]`，`MEDIA_IMAGE_MODEL` env 仍作运行时覆盖（优先级最高，保留）。

2. **#23 ProjectInviteRecord 提到 shared**（`packages/shared/src/api-contracts.ts`，紧挨 `ProjectInviteSummary`）：
   ```ts
   export interface ProjectInviteRecord {
     id: string; projectId: string; email: string; role: ProjectRole;
     createdBy: string; status: "pending" | "accepted"; createdAt: string;
   }
   ```
   - `workspace.service.ts`：删 L97-106 本地定义，import 加 `ProjectInviteRecord`。
   - `legacy-database.types.ts`：删 L37-45 本地定义，import 加 `ProjectInviteRecord`（类型复用零运行时影响，不违反 AGENTS.md 的 legacy 隔离原则——隔离的是运行时数据，不是编译期类型）。

## 风险与缓解
- **改动一**：返回类型零变化、测试无字段级断言，风险极低。getReviewQueue 的 where 收窄同时修复跨租户隔离隐患。
- **改动二**：删 enum 的 DROP TYPE 迁移在 enum 无字段引用时安全；worker Pick 类型比内联更严格（id 必填），若 API 返回缺 id 会在编译期暴露。
- **改动三**：web/API 视频 model 已确认一致；图片 `gpt-image-1` 收敛时保留 `MEDIA_IMAGE_MODEL` env 覆盖层。ProjectInviteRecord 两份定义字段等价，合并零行为变化。
- **改动四**：messages.ts 必须中英对称（结构镜像），新增 timeline 命名空间要同时在 zh 和 en 各加一份。
